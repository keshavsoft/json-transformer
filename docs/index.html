The Mental Model & Ownership Story

In data processing, systems often break when the boundaries of ownership are violated. JSON Transformer enforces absolute separation of responsibilities:

Data Provider
SOURCE JSON

Raw data from external APIs, databases, XML exports, or Tally. Never modified merely to fit output shapes.

Application Domain
TRANSFORMATION

The declarative output recipe. Specifies field selection, nesting, renaming, array iteration, and conversions.

Consumer Ready
OUTPUT JSON

The synthesized result. Clean, structured, and tailored for user interfaces, ingestion, or downstream services.

Key Invariant: The source can belong to another vendor. The transformation belongs to the application. The output belongs to the consumer.

Declarative Data & DOM Architecture

Together, three focused libraries create a lossless, end-to-end bridge between live HTML DOM trees and enterprise business data:

1
tag-to-json

Captures native live HTML DOM trees and extracts them into clean, declarative JSON specifications.

2
json-transformer

Transforms heterogeneous raw data (APIs, Tally/XML, SQL) into canonical target data shapes and UI specifications.

3
json-to-tag

Compiles declarative JSON specifications directly into high-speed, interactive native DOM elements.

01 Foundations
Concepts

The foundational mental model: data ownership, recursive composition (object → array → object), scalar current value, and non-destructive bridging.

SOURCE + TRANSFORMATION → OUTPUT
02 Internals
Architecture

Internal pipeline design: strict separation between Traversal (interprets instructions) and Resolution (resolves paths in source data).

traverse.js ⇄ resolve.js ⇄ value.js
03 Language
Mapping Language

Grammar specification: item for object recipes, list for collections, "" for scalar values, and root escapes.

{"mapping": {"item": {"a": "A"}}}
04 Collections
Arrays & Collections

Iterating repeating collections, deep nested hierarchies (orders → items → batches), and scalar lists without ad-hoc code paths.

voucher[] ➔ inventory[] ➔ batch[]
05 Resolution
Path Resolution

Handling ordinary dotted traversal (a.b.c), literal dotted keys in XML (LEDGERNAME.#text), and root resolution (^path).

LEDGERNAME.#text ⇄ ^root.company
06 Enterprise
Tally & XML Case Study

Consuming enterprise accounting vouchers and complex XML payloads without contaminating the core transformer engine with Tally specifics.
