Document 7 — Understanding the Function

The traversal engine knows where it is in the source. The function receives that information and decides what to do with it.

1. We Already Have the Tree

The previous documents showed how a source structure can be traversed according to an instructions object.

We also saw that a function can be attached to the resulting leaves.

Now we will stop looking at the tree for a moment and look only at the function.

2. The Function Is Supplied From Outside

The traversal engine does not need to know what the function actually does.

The application supplies the function. 

function inspect(value, path, source, instruction) {
  console.log("Value:", value);
  console.log("Path:", path);
  console.log("Source:", source);
  console.log("Instruction:", instruction);
}

The important question is therefore: what does each argument mean?

3. The Four Inputs

value   +   path   +   source   +   instruction

4. The First Input — value

value is the actual value found at the current location in the source. 

{
  "customer": {
    "name": "Keshav"
  }
}

If the current location is customer.name, then: 

value === "Keshav"

This is the most direct information given to the function: what is present here?

5. The Second Input — path

path tells the function where the current value was found. 

path === "customer.name"

The value tells us what we found. The path tells us where we found it. 

value
  ↓
"Keshav"

path
  ↓
"customer.name"

6. The Third Input — source

source represents the complete source structure being traversed. 

{
  "customer": {
    "name": "Keshav",
    "email": "keshav@example.com"
  },

  "order": {
    "id": "ORD-101"
  }
}

Even though the function may currently be operating on customer.name, it can still be given the complete source when broader context is useful.

Therefore: 

value   → the current value

path    → the current location

source  → the complete source

7. The Fourth Input — instruction

instruction represents the instruction that caused the function to be used at this location.

For example: 

{
  "transform": "inspect"
}

The function can therefore know not only the value and its location, but also the instruction associated with that location.

8. Putting the Four Inputs Together

function inspect(value, path, source, instruction) {

  // What is here?
  console.log(value);

  // Where is it?
  console.log(path);

  // What is the complete source?
  console.log(source);

  // Why was this function attached here?
  console.log(instruction);
}

The four inputs answer four different questions: 

value
  → What is here?

path
  → Where is it?

source
  → What is the complete structure?

instruction
  → What instruction applies here?

9. The Function Does Not Traverse

This distinction is important.

The function itself does not need to know how to walk through customer, then name, then another branch.

The traversal engine has already done that work.

Source
↓
Traversal
↓
Current location found
↓
Function receives its four inputs

The function can therefore remain completely focused on its own job.

10. A Runtime Example

Suppose the source is: 

{
  "customer": {
    "name": "Keshav"
  }
}

And the instruction at customer.name is: 

{
  "transform": "inspect"
}

When traversal reaches that location, the function can receive: 

inspect(
  "Keshav",
  "customer.name",
  {
    customer: {
      name: "Keshav"
    }
  },
  {
    transform: "inspect"
  }
);

11. What the Function Now Knows

Without performing any traversal itself, the function knows:

  • the value it is operating on;
  • where that value exists in the tree;
  • the complete source structure;
  • the instruction associated with that location.

That is the real purpose of the function interface.

12. The Important Separation

The traversal engine knows how to navigate. The function knows what to do.

This separation is what keeps the function independent from the traversal mechanism.

The engine supplies the context. The application supplies the behavior.

13. The Mental Model

SOURCE
   ↓
TRAVERSAL
   ↓
current node
   ↓
┌─────────────────────────────┐
│ value                       │
│ path                        │
│ source                      │
│ instruction                 │
└─────────────────────────────┘
   ↓
FUNCTION
   ↓
application behavior

So the function does not need to understand the tree-building process. It receives a precise description of where it has been called and the information available at that location.
