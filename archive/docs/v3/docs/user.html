The User Guide Recipe Author

The Recipe Author's handbook: How to transform heterogeneous enterprise data into clean, predictable JSON with zero side effects.

1. The Core Story: The Food, The Recipe & The Kitchen

When you build modern applications, you inevitably consume data from external enterprise systems—Tally ERP, SAP, SQL databases, or legacy SOAP/XML APIs. This data arrives in rigid, verbose formats riddled with XML artifacts like #text, attributes like @_TYPE, and capitalized keys.

Traditional developers solve this by writing brittle imperative loops and mutative scripts. When an optional field disappears or an array turns into a single object, the entire pipeline crashes.

@keshavsoft/json-transformer solves this with an unshakeable invariant:

🥗
structure.json
The Food • Untouchable
Source data belonging to the external producer (Tally, SAP, client API). It is sacred and 100% immutable. The engine never modifies it.
📜
data.json
The Recipe • Declarative
Your transformation blueprint. It codifies domain knowledge: which keys to keep, what to rename, how to unwrap text, and how to nest structures.
⚙️
json-transformer
The Kitchen • Pure Compiler
A deterministic, zero-dependency compiler: (food, recipe) → result. It produces the transformed dish without altering the original ingredients.
The KeshavSoft Declarative Ecosystem: json-transformer is the middle engine in a complete 3-part declarative web ecosystem:

1. tag-to-json (DOM → JSON Spec)  •  2. json-transformer (Data → Clean Spec)  •  3. json-to-tag (Spec → Reactive DOM)

2. Why Two Separate JSONs? The Immutability Principle

A common question is: "Why can't I just embed transformation rules directly into the source JSON?"

Embedding instructions inside data violates architectural separation for three fundamental reasons:

  1. Client Data is Sacrosanct: Upstream data comes from external producers. Mutating it in place corrupts shared memory references, invalidates caches, and triggers subtle downstream regressions.
  2. Preventing Infinite Loops: If a recursive engine mutates data while traversing it, circular references and self-referencing branches trigger infinite execution loops.
  3. Independent Lifecycles: The Food changes on every single API request or database query. The Recipe changes only when your business contract evolves. Decoupling them keeps your application deterministic and rock-solid.

The Recipe is Domain Proof, Not Duplicate Effort

Why does the recipe mirror the path of the source data? Because you cannot transform complex enterprise data without first proving you understand its hierarchy.

When you write a recipe, you formally codify: "I know that STOCKITEM contains BATCHALLOCATIONS.LIST, which contains GODOWNNAME." Any key you do not explicitly acknowledge is safely filtered out, preventing unwanted data leaks into your output.

4. The Directive Vocabulary

Recipes are constructed using four clean declarative directives:

Directive Type Purpose Example
alterKey string Renames the matching source property on the output object. { "alterKey": "StockItems" }
transform object Nests transformation directives for child objects or arrays. { "transform": { "NAME": { ... } } }
valueKey string Extracts a child property (e.g. #text) directly, unnesting it. { "valueKey": "#text" }
valueType "array" Guarantees output is wrapped in an array even if input is a single object. { "valueType": "array" }

5. Real-World Recipe Cookbook

Scenario A: Unwrapping XML Text Nodes

When XML converters output text wrappers like BASEUNITS: { "#text": "kgs", "@_TYPE": "String" }:

// The Recipe
{
  "transform": {
    "BASEUNITS": {
      "alterKey": "Units",
      "valueKey": "#text"
    }
  }
}

// Output: { "Units": "kgs" }

Scenario B: Tally Batch Allocations

Tally stock records store batch lists under BATCHALLOCATIONS.LIST. When there is only one batch, Tally outputs a lone object. We normalize it to a clean array and extract only godownName:

// The Recipe
{
  "transform": {
    "BATCHALLOCATIONS.LIST": {
      "alterKey": "Batches",
      "valueType": "array",
      "transform": {
        "GODOWNNAME": {
          "alterKey": "godownName"
        }
      }
    }
  }
}

6. Using @keshavsoft/json-transformer in Code

Install via npm:

npm install @keshavsoft/json-transformer

Execute in your JavaScript or TypeScript modules:

import transform from "@keshavsoft/json-transformer";

const food = {
  STOCKITEM: [
    {
      NAME: "Item A",
      BASEUNITS: { "#text": "kgs" }
    }
  ]
};

const recipe = {
  transform: {
    STOCKITEM: {
      alterKey: "Items",
      transform: {
        NAME: { alterKey: "name" },
        BASEUNITS: { alterKey: "units", valueKey: "#text" }
      }
    }
  }
};

const result = transform(food, recipe);
console.log(result);
// { Items: [ { name: "Item A", units: "kgs" } ] }
