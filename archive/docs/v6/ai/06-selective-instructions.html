Document 6 — Selective Instructions on a Larger Source

We have already seen that the structure can grow by adding new roots and children without changing the traversal mechanism.

Now we make the source considerably larger. The important point is that the source can contain much more information than the instructions need to address.

Instructions are mandatory. A node is acted upon only when an instruction exists for that node. There is no fallback behavior in this example.

1. A Larger Source

Imagine that our source contains several parts of an order: 

{
  "customer": {
    "name": "Keshav",
    "email": "keshav@example.com",
    "phone": "9876543210"
  },

  "order": {
    "id": "ORD-101",
    "date": "2026-10-07",
    "status": "confirmed"
  },

  "product": {
    "code": "P-100",
    "name": "Laptop",
    "price": 75000
  },

  "shipping": {
    "address": {
      "city": "Kakinada",
      "state": "Andhra Pradesh"
    },
    "method": "Express"
  }
}

This is a reasonably large source compared with our previous examples. But the traversal engine does not need to become more complicated.

2. Instructions Are the Important Part

We do not have to attach a function to every value in this source. Instead, we explicitly describe the locations we want to act upon. 

{
  "customer": {
    "name": {
      "transform": "logPath"
    }
  },

  "order": {
    "id": {
      "transform": "logPath"
    }
  },

  "shipping": {
    "address": {
      "city": {
        "transform": "logPath"
      }
    }
  }
}

Notice what happened. The source is large, but the instructions are small.

Only three locations have instructions. Therefore, only those three locations become function points.

3. The Function Comes From Outside

The traversal system does not need to know how logPath works. The function is supplied from outside. 

function logPath(value, path) {
  console.log(
    "I am here in the tree:",
    path,
    value
  );
}

The traversal encounters an instruction, resolves what that instruction means, and uses the supplied function at that location.

4. What the Traversal Sees

The source is still traversed normally. The instructions are consulted when the corresponding source node is encountered. 

customer
  └── name
      → transform → logPath

order
  └── id
      → transform → logPath

shipping
  └── address
      └── city
          → transform → logPath

Other source values such as customer.email, customer.phone, order.date, product.price, and shipping.method have no instruction in this example.

They therefore do not receive the function.

5. Runtime Output

I am here in the tree: customer.name Keshav
I am here in the tree: order.id ORD-101
I am here in the tree: shipping.address.city Kakinada

6. The Resulting In-Memory Object

The resulting object preserves the larger source structure, while the instructed locations contain the supplied function. 

{
  customer: {
    name: logPath
  },

  order: {
    id: logPath
  },

  shipping: {
    address: {
      city: logPath
    }
  }
}

7. The Important Idea

The source can be large. The instructions can be small. The instructions decide where behavior is attached.

Nothing special was added to the traversal algorithm because the source became larger.

We simply supplied a different instruction structure.

The progression is still: 

Source
   ↓
Traverse the source
   ↓
Consult the instructions
   ↓
Resolve the instruction
   ↓
Use the supplied function
   ↓
Continue through the source

8. Why This Matters

This example shows an important separation:

  • The source describes what exists.
  • The instructions describe what should happen.
  • The function provides the behavior.

A very large source therefore does not force us to create a very large instruction set. We can select only the parts of the structure that matter.

The traversal mechanism remains completely unchanged.
