Document 2 — How It Works

1. The Core Idea

Given three inputs:

  1. a structure (the source),
  2. an instructions object (the recipe), and
  3. a function (the leaf behavior),

the engine traverses the source structure, consults the instructions as it encounters each source node, and produces an in-memory object with the function attached to every leaf.

The Core Invariant:
The source is traversed. The instructions are consulted.
The engine does not traverse the instructions object.

2. Source-Driven Traversal

The traversal begins with the source. At each point in the source, the engine executes this decision cycle: 

What is the current source node?
        ↓
Is there an instruction for this node?
        ↓ (yes)
Seek and resolve that instruction
        ↓
Understand what the instruction specifies
        ↓
Apply that instruction to the current source node
        ↓
Continue traversing the source

3. Why Source-Driven Matters

Because traversal is driven by the source, the instruction object never needs to duplicate the entire source tree. If the source contains dozens of properties, but only two have instructions, the engine seamlessly walks the source and only attaches behavior where instructed.

Source data exists → Traversal encounters node → Consults recipe → Attaches leaf function
