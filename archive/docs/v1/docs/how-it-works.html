How It Works

Under the hood of the recursive transformation engine.

1. The Central Dispatcher (traverse.js)

When you invoke transform(source, recipe), execution enters traverse.js. The dispatcher inspects the data type of the source node:

  • If inSource is an Array ➔ delegates to traverseArray.
  • If inSource is an Object ➔ delegates to traverseObject.
  • Otherwise (primitive string, number, boolean) ➔ returns the value untouched.

2. The Decision Point: The Recipe Check (Line 14 Rule)

Inside traverseObject, the engine performs a critical check:

if (localRecipe && typeof localRecipe === "object" && "transform" in localRecipe) {
    newElement = ifTransformFound({
        inSource: localSource,
        inTransform: localRecipe.transform
    });
}

Notice carefully: The check is on the Recipe, not the source! The engine asks: "Does the recipe define instructions for this level?"

If "transform" is present in the recipe, the engine unwraps only that directive block and delegates to ifTransformFound.

3. The Execution Phase: Source Becomes the Driver

Inside ifTransformFound, the roles flip completely:

for (const [key, value] of Object.entries(localSource)) {
    if (!(key in localTransform)) {
        continue;
    }

    const directive = localTransform[key];
    const newKey = directive?.alterKey || key;
    // Apply nested transforms, valueType, or valueKey
}

Here:

  • localSource is the Source of Truth driving the loop.
  • localTransform acts strictly as the Lookup Table.
  • Keys not present in the recipe are skipped automatically.
  • If a key has an alterKey directive, the output object receives the rewritten property name.
  • If a key has a nested transform directive, the engine recursively calls traverse to dive into child objects or arrays.

4. Array Handling (traverseArray)

When arrays are encountered, traverseArray maps each element through traverse using the current recipe level, flattening results and pruning empty nodes.
